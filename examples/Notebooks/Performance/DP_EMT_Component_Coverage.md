# DP/EMT Component Coverage Ledger

Generated from the current implementation inventory under `dpsim-models/src/DP` and `dpsim-models/src/EMT` (157 C++ translation units). This is a tracking ledger, not a claim that every file defines exactly one concrete class. Derived classes sharing a base must still be checked for overrides and state-specific work.

The 157 source-file inventory is represented by 157 primary component rows; additional rows record follow-up optimization trials for an already-listed source file. The current table therefore contains more rows than implementation files.

The audit also tracks adjacent SP and Signal domains (36 SP and 29 Signal implementation files). Their inventory is being added separately from the DP/EMT table below; only explicitly listed classes have class-level evidence recorded here.

`Representative/group-tested` means the file is covered by at least one validation described in [DP_EMT_Runtime_Audit.md](DP_EMT_Runtime_Audit.md); it does not mean all concrete classes or configurations in that file are complete. Rows with a specific limitation remain unfinished for that class/configuration. Update each row only when supported by source inspection and correctness/performance evidence.

### Additional DP/EMT runtime-path cross-checks

- `EMT::Ph3::SynchronGeneratorDQ::calculateNumericalJacobians()` allocates
  perturbation vectors, but repository call-site inspection shows it is not
  used by simulation. The runtime `buildStateSpaceModel()` uses the analytic
  Jacobian instead, so optimizing the numerical helper would not improve
  simulation time.
- The EMT DQ generator compensation branch is gated by `mCompensationOn`.
  `initializeMatrixAndStates()` sets it false, both EMT DQ-derived classes call
  that initializer, and no source/API setter enables it. The normal timestep
  path therefore does not execute its compensation-current division; no
  reciprocal-caching change is applicable without changing protected model
  behavior.
- `EMT::Ph3::SSN_GFM::calculateNumericalJacobians()` is likewise not called by
  simulation; `buildStateSpaceModel()` calls `calculateAnalyticalJacobians()`.
  The active state-dependent analytical Jacobian work is required, while the
  numerical helper's per-call scratch is diagnostic-only.

### SP PiLine power-flow stamping follow-up

`SP::Ph1::PiLine::pfApplyAdmittanceMatrixStamp()` rebuilds its 2×2 element
admittance on each power-flow matrix assembly. The formula depends on live
per-unit parameter fields and PF-vs-initialization behavior, so caching the
admittance across assemblies would require invalidation and is not safe as a
simple timestep optimization. The obvious lower-risk candidate—reusing the
existing `mY_element` allocation rather than assigning a freshly constructed
dynamic matrix—was deferred without implementation: the current IEEE9 SP
executable completes a one-step setup/run in about 0.01 s, below the timer's
useful resolution for isolating this initialization-only work. A larger
PF-only repeat fixture is needed before claiming this as a runtime improvement.

### Grouped EMT retained-node index cache

`EMT::LinearSSNGroup` now caches the retained terminal matrix rows when its
system stamp is built and reuses them in per-step terminal-voltage gathering
and history RHS scatter. The sparse maps and all arithmetic are unchanged; the
optimization removes repeated `matrixNodeIndex()` lookups from two hot loops.
The IEEE118 fully reduced grouped case at 10 s / 50 µs completed five baseline
runs in 32.59, 36.53, 32.78, 32.60, and 32.04 s (median 32.60 s), and five
candidate runs in 31.79, 31.99, 31.82, 31.93, and 32.04 s (median 31.93 s), a
2.1% median reduction. A logged 1 s / 50 µs baseline/candidate comparison had
10,002 rows in each trace and was byte-identical. The candidate build and
target completed successfully. The five-run batches were sequential, not
interleaved; the median comparison is reported because the baseline includes a
36.53 s outlier.

The group also has fine-grained `steady_clock` timing counters in its hot
callbacks. An experiment gated those counters off in normal runs and enabled
them only in detailed-profile mode. Five additional 10 s / 50 µs runs with
timing gated off averaged 32.17 s (median 32.23 s), versus 31.91 s (median
31.93 s) with the counters always active; this did not show a repeatable
speedup and trended 0.8% slower. The toggle was reverted to avoid adding an
unproven branch/configuration; the existing detailed counters remain.

A second small group trial removed `terminalVoltage()`'s zero-fill because the
post-step loop assigns every retained phase entry. The candidate was built and
tested on five 1 s / 50 µs runs: baseline mean/median were 3.30/3.29 s, while
candidate mean/median were 3.41/3.30 s (one 3.87 s candidate outlier). No gain
was resolved, so the zero-fill remains in the implementation.

The isolated fully reduced 10 s / 50 µs detailed profile attributes 16.78 s
to the group's complete state-update callback, 1.86 s to the reduced history
map multiply, and 0.033 s to RHS scatter (200,000 calls each). The reduced
state map has 108,336 stored coefficients; reduced history and input maps each
have 12,108. This confirms that state-map application, not terminal-index
gather/scatter, is the major remaining group-local cost. These are instrumented
callback times, not exclusive wall-time contributions.

The fully reduced state update now applies the compressed row-major map with a
direct CSR row loop, then keeps Eigen's existing sparse product for the smaller
input map. The map is 4,560×4,560 with 108,336 entries (0.52% density; 0–106
entries per row). Five IEEE118 10 s / 50 µs baseline runs averaged 31.73 s
(median 31.78 s); five candidate runs averaged 31.25 s (median 31.18 s), a
1.5% mean and 1.9% median reduction. All five candidates were faster than all
five baseline times. The 1 s / 50 µs 10,002-row logged trace was byte-identical
to the Eigen-product baseline. Other grouped execution modes retain their
existing paths.
