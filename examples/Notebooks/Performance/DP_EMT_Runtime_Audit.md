# DP/EMT Runtime Optimization Audit

Status: in progress. The goal covers all DP and EMT component classes; this
file records verified work and outstanding coverage rather than implying that
the audit is complete.

## Full IEEE118 DP solve-stage profile (30 s, 1 ms step)

Collected with the existing `IEEE118_Ph3 dp conventional profile` case. The
profile completed 29,999 timestep solves. The `Solve` task accumulated 2.317 s;
its measured subphases were numeric solve 1.388 s (46.26 µs/step), dense RHS
stamp accumulation 0.701 s (23.37 µs/step), compact RHS callbacks 0.171 s
(5.70 µs/step), node-voltage propagation 0.041 s (1.36 µs/step), and RHS zeroing
0.005 s (0.18 µs/step). Switch-status update was below 1 ms total. The matrix
was factored once (0.917 ms); no repeated refactorization was observed. A
follow-up one-second profile confirms the active fixed matrix is 1,956×1,956
with 38,652 stored entries (1.01% density).

To expose these phases on the normal fixed-matrix solve path, `MNASolverDirect`
now records numeric solve, switch-status update, node propagation, RHS zeroing,
and iterative-generator checks/updates when detailed solver profiling is
enabled. These timers are disabled outside profiling. The numeric solve and
RHS accumulation dominate this case; node propagation is not a large remaining
cost. Matrix statistics now select the active switched matrix for fixed-matrix
runs instead of the unused variable matrix, and the one-second profile verifies
the corrected dimensions. Solver alternatives at identical DP settings remain
a follow-up comparison. Five logger-free 30 s runs with profiling disabled took
5.40, 5.33, 5.46, 5.37, and 5.42 s (mean 5.396 s); this is a disabled-path
sanity check, not a matched before/after speedup claim.

The measured dense RHS work was then removed from the DP IEEE118 VBR-generator
path with a direct compact callback that writes only its three active phase
rows (real and imaginary). A 30 s logged baseline/candidate comparison was
byte-identical (SHA-256
`1693bd9c5427d63ecc3a8e67850a2a8e402f89f204214d8e20f0d1139142d001`). Five
interleaved logger-free 30 s runs averaged 5.406 s baseline vs 4.758 s
candidate (12.0% faster, 5/5 paired wins). Candidate profiling recorded zero
dense RHS component calls instead of 54 per step. The profiler's residual
`rhs_dense_stamp_accumulation` phase fell from 0.701 s to 0.169 s; the remaining
candidate phase is dispatch/loop overhead, not dense vector additions. This is a
repeatable workload-level win and supersedes an earlier compact callback trial
that was slower.

A shared `CompositePowerComp` aggregation trial grouped cached child RHS
contributions by output row to combine clearing and accumulation into one pass.
The 30 s IEEE118 DP trace remained byte-identical, but five interleaved runs
averaged 4.744 s baseline vs 4.884 s candidate (3.0% slower, 5/5 candidate
regressions). The trial was reverted; the current clear-then-accumulate path is
faster for the measured composite workload.

Two compact RHS micro-optimizations for DP Ph3 capacitors and inductors were
also tested because their callbacks are used by IEEE118 loads and line
subcomponents: (1) cache terminal rows/connectivity and write real/imaginary
entries directly, and (2) keep runtime index/ground checks but bypass the
complex-add helper. Both 30 s IEEE118 traces remained byte-identical. The
cached-row variant averaged 4.776 s baseline vs 4.836 s candidate (1.3%
slower, candidate lost 4/5 pairs); the helper-only variant averaged 4.782 s vs
4.834 s (1.1% slower, candidate lost 4/5). Both were reverted; the current
compact callback implementation is faster at this network scale.

## Solver correctness regression found during component audit

The KLU system-matrix recomputation path reset a variable matrix by copying the
static matrix's coefficient array positionally. That was invalid whenever a
variable component inserted additional sparse entries: the static and variable
matrices did not necessarily share the same sparse pattern or coefficient
ordering. The reset matrix is now built on the variable matrix's full sparse
pattern, with explicit zero values at variable-only positions, so value-only
resets remain valid. A new `EMT_Ph1_Switch_Audit` fixture runs both recomputation
and precomputed-switch modes. At 20 µs for 1 s, both modes produced 50,001
finite samples and byte-for-byte identical logged traces; the circuit correctly
transitions from 1 mV/100 µA with the switch open to about 99.01 V/9.90 A closed,
then returns to the open values after the second event. Before the fix, the
recomputation run remained electrically closed after the open event. Five-run
mean wall times after the fix were 0.2434 s (recomputation) and 0.2337 s
(precomputed-switch mode); this is a mode comparison, not a before/after speedup
claim. This regression is also evidence that the sparse-reset optimization
requires exact pattern alignment, not merely equal dimensions.

## Verified optimization phases

### EMT monolithic GFL relinearization workspaces

`SSN_GFL::buildStateSpaceModel()` previously allocated state-derivative and
output vectors plus local affine-offset matrices on every timestep. These are
now per-instance workspaces; the analytic Jacobian remains unchanged, and
affine offsets still subtract `A*x`, `B*u`, `C*x`, and `D*u` in the original
order. The existing `EMT_Ph3_GFL_Comparison --monolithic-gfl-repetitions 5 10`
fixture was used at 10 s / 100 µs.

Five baseline runs averaged 1.7953 s. Ten candidate runs in two independent
batches averaged 1.6918 s (5.8% lower); the second five-run batch averaged
1.7201 s (4.2% lower than baseline). Excluding the anomalous divergent run,
the four finite baseline runs averaged 1.8452 s and nine finite candidate
runs averaged 1.7148 s (7.1% lower). Baseline and candidate each reproduced
the same divergent output trace hash
`9049de3322a80abdaaf38fbfc408547f3cb1b59a9bf957c150139418251f8980`; all
finite runs had 100,001 rows and byte-identical hash
`221eb42baa6abfd57e39c16db92dbff9f9d14c22c26fcc70cedf492b3f4bdace`.
The workspace change did not create the divergent trace, but long-run
stability of this GFL fixture remains a separate limitation.

### Load-dense EMT nonlinear PQ-load path

Added `EMT_Ph3_PQLoad_GridBenchmark`, a separate 128-parallel-load fixture on
one three-phase bus (0.5 s at 50 µs, 10,000 steps). It changes every load's
active-power setpoint at 0.3 s and reactive-power setpoint at 0.4 s, while
logging one representative load's voltage, current, measured P/Q, and
iteration count. In `calculateCurrent()`, the fixed three-element input is
checked directly, its phase values and arithmetic mean are scalar, and the
live setpoint attributes are read once per invocation. The current formula
and nonlinear correction behavior are otherwise unchanged.

Five baseline runs averaged 361.897 ms; five candidate runs averaged 324.689
ms (10.3% lower, all five candidate runs faster). Every paired CSV was
byte-identical, with 10,001 finite rows and SHA-256
`149bc5439d02cc1162b3508eb9e0a88d284bf8ed3b6ec48b89a14df7447b670a`. The
logged per-load P/Q values show both events taking effect at their scheduled
times. This resolves the earlier load-dense scaling limitation for the
specific 128-load parallel case; larger topologies remain useful validation.
The original 0.5 s/50 µs single-PQLoad example was also rerun five times; all
five traces matched the previously saved SHA-256
`a00d460ce1a5ab27e9c685867cde1a65513d039ba2b4048ec5f7b6a67369656c`.

### One-phase EMT passive RHS/access trial (reverted)

The one-phase capacitor and inductor timestep paths were tested with direct
access to the base class's cached interface-value pointers and terminal-row /
ground flags, retaining the original RHS overwrite behavior. Five paired
`EMT_Ph1_General2TerminalSSN` runs covered C1R1 RC, L1R1 RC, and RLC RC cases;
all corresponding CSV traces remained byte-identical. Calculation means were
5.594→5.888 ms (C1R1 RC), 5.176→5.199 ms (L1R1 RC), and 5.179→4.923 ms
(RLC RC). The single mixed result did not establish a repeatable cross-case
gain, so both source changes were reverted. An initial draft that changed RHS
overwrite into accumulation also changed traces and was discarded before
benchmark interpretation.

### DP single-phase inverter relinearization workspace

`DP_Ph1_AvVoltSourceInverterStateSpace` now reuses fixed-size derivative and
affine-offset workspaces across timestep relinearization instead of allocating
the RHS vector and local E/F matrices on every call. The affine offset is
assembled in place while preserving the order of the two Jacobian products.
At 10 µs for 0.1 s, five baseline calculation-time runs averaged 121.732 ms;
the second five candidate runs averaged 120.109 ms (1.3% lower; medians 121.219
and 119.712 ms). Ten candidate runs produced the same finite 10,001-step trace
with SHA-256
`f08e9f58514ed5acc20f6186de3f5bbbeaf6d12012e35cbaa9e5f678ead657f0`.
This is a small local improvement on a short stable fixture, not a demonstrated
network-scale gain.

### Frequency-parallel switch-matrix follow-up

The sequential and parallel inverter examples now accept opt-in
`-o switch=true`. This adds an ideal DP shunt switch, closes it at 20 ms, and
reopens it at 40 ms, exercising matrix stamping/factorization across switch
states and frequencies while leaving their default topology unchanged. The
fixture first exposed two further correctness defects: DP switches were not
initialized in the harmonic MNA path, and each harmonic solve selected a stale
shared switch-state key. The solver now initializes switch interfaces before
matrix construction; each frequency worker derives its own switch-state key
from the current switch attributes, avoiding a shared write/data race. Before
20 ms the switched trace follows the unswitched trace; after closing, the
network response changes. Sequential and four-thread 50 ms / 1 µs traces have
50,002 rows, are finite, and match byte-for-byte (SHA-256
`e3ab27282111953ddfd907e8310701afe1dd72b583b97de1ef47f2726770221f`). This is
solver-path correctness validation, not a new timing claim.

### Shared matrix-node-index refresh audit

The DP/EMT source scan finds 91 calls to `updateMatrixNodeIndices()`. Most are
in MNA initialization or system-matrix stamping, not timestep callbacks. A
base-class “refresh once” cache was not introduced: component terminals can
be replaced through `connect()`/`setTerminals()`, and node matrix indices are
assigned by each solver initialization, so a lifetime-only cache could become
stale when a component is reused in a differently ordered system. The hot
grouped callback was optimized locally after its exact 10 s benchmark showed
that its terminal set is fixed for the run. Further removals should be
class-specific and tied to measured step callbacks rather than changing the
shared cache contract.

The grouped callback now also stores its retained global matrix rows when its
system stamp is applied, then reuses those rows for both terminal-voltage
gathering and compact RHS scatter. The IEEE118 fully reduced grouped case at
10 s / 50 µs measured five sequential baseline wall times of 32.59, 36.53,
32.78, 32.60, and 32.04 s (median 32.60 s), versus candidate times of 31.79,
31.99, 31.82, 31.93, and 32.04 s (median 31.93 s). The median improved 2.1%;
the baseline batch contains a 36.53 s outlier, so this is a small sequential
batch, not an interleaved estimate. The logged 1 s / 50 µs traces were exactly
identical at all 10,002 rows. This is an additional local optimization; it
does not eliminate the substantial sparse-map products still performed each
step.

The follow-up isolated 10 s / 50 µs profile attributes 16.78 s to the complete
group state-update callback, 1.86 s to the reduced-history map multiply, and
0.033 s to RHS scatter (200,000 calls each). The fully reduced state map has
108,336 stored coefficients; reduced history/input maps each have 12,108.
Removing the terminal-input workspace zero-fill showed no runtime gain in five
1 s runs and was reverted. Gating the always-on per-step detailed timers off
for normal runs also showed no gain (five-run means 32.17 s off vs. 31.91 s
on) and was reverted. The large state-map operation remains the next measured
group-local target; these instrumented sub-times are not exclusive wall-time
contributions.

Because the reduced state map is 4,560×4,560 but only 0.52% dense, the fully
reduced state update now uses a direct compressed-row loop for the dominant
state-map product; Eigen remains in use for the smaller input-map product.
Five fresh IEEE118 10 s / 50 µs baselines averaged 31.73 s (median 31.78 s),
and five candidates averaged 31.25 s (median 31.18 s), with every candidate
faster than every baseline run. A logged 1 s trace was byte-identical across
10,002 rows. This change applies only to the fully reduced map mode; shared-map
and baseline modes are unchanged.
